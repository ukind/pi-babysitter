### F021+F022 — per-token refspec matcher (scripts/hooks/gate.mjs:62-81)
- Current signals: `flagForced = /\s--force(?!-with-lease)\b|\s-f\b/` at gate.mjs:69 (string-level; lookahead suppresses --force-with-lease) and `plusForced` boolean scan at :70 (which-token discarded). :71 returns false when neither fires — this guard is what keeps plain `git push origin main` allowed.
- Root cause: the rejoin at :74-76 strips `+` from ALL tokens and joins; the regex at :77-79 anchors on whitespace, so `refs/heads/main` hides `main` behind `/` (bypass: `git push --force origin refs/heads/main` passes) and any whitespace-delimited `main` convicts once `+` is erased (false positive: `git push origin main +feature/x` blocks).
- The audit's regex-widening-only fix would keep the false positive; the FRD correctly adopts per-token matching instead (FRD Decision "F021 and F022 share one per-token fix").
- Verified replacement shape (checkpoint decision: any-source arm):
  - Force attribution per token: `forced := token.startsWith("+") || flagForced` — `+` forces only its own token; an explicit flag forces every refspec (git semantics).
  - Protected-branch token shape: `^(?:[^:]+:)?(?:refs/heads/)?(?:main|master)$` — optional any-source prefix before the colon (protection keys on the DESTINATION, which is why `+main:main` at tests/test.mjs:1122 stays blocked and `HEAD:refs/heads/main` blocks), optional `refs/heads/` on either side, terminal branch.
  - Existing fixtures stay green under this shape: `--force-with-lease origin main` (flag suppressed, no `+`, no token forced → allowed); `--force-with-lease origin +main` (plus path → blocked, tests/test.mjs:1120); `origin main +main` (tests/test.mjs:1121) stays blocked but now for the CORRECT reason (its `+main` token), no longer by coincidence.
  - Bonus bypass covered automatically: `git push origin --force refs/heads/main` (flag after remote) — worth a fixture; the audit did not list it.
- Fixture impact in t19b (tests/test.mjs:1109-1142): append 3 blocked entries inside `blocked` (:1112-1123), update the count pin :1127 to 13, append `git push origin main +feature/x` inside `allowed` (:1134-1138, no allowed-count pin exists). - Hub-and-spoke star topology with zero sibling imports among pure modules is what makes this pass cheap: every fix site is importable and testable offline, and the only cross-module contracts are the injected thunks (gates, resolve, strip) and the {ok, reason}/{ok, detail} result shapes.

- Per-dispatch config re-read (config.ts:170) plus per-field narrowing means shipped-file content is policy: whatever is tracked in config.json IS the default experience for clones. Untracking removes the class of bug, not just the instance.
- Pinned strings are contract: gate reason (gate.mjs:91), failure reasons, warn-once messages, t20's detail, t11's message. Fixes must preserve or explicitly re-pin them; the count pins (t19b :1127) are the one deliberate exception to update.
